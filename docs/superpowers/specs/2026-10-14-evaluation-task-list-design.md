# 评测任务列表与详情设计

日期：2026-10-14；基线：dev/ad9bb3c。

用户已指定：评测列表与现有任务列表接近，未来承载其他类型；点击具体评测任务再展示详情。本方案替代上一版默认双栏展示和“当前衔接优先”的草案。

## 流程

评测顶栏入口 → 右侧评测任务列表 → 点击具体任务 → 任务详情 → 返回同一列表位置。

列表宽约 680px，沿用现有任务抽屉的标题、刷新/关闭、状态指标、缩略图与行式记录。列表行统一包含类型标签、评测对象、模型/时间/任务编号、执行状态和结果摘要。已完成与结果需关注是不同概念：完成状态可搭配低分或低置信度标记。过期记录明确标记历史结果。列表不默认打开任何详情。

“全部 / 进行中 / 已完成 / 失败”按服务端筛选并分页，搜索按任务对象、模型与编号在全量记录筛选，不冒充页内全量检索。计数保持全部记录范围；筛选后的总数单独显示。轮询只 GET，并保留用户页码和选中任务；切换版本编号、筛选或主动翻页清空旧选择且处理异步竞态；同一版本修订刷新和自动缩页保留已选详情。读取失败保留已加载记录并显示错误；无历史任务显示明确空状态与“发起评测”操作。

详情使用宽内容面板，保留冻结的前后镜头边界图、状态、总体和四维评分、置信度、问题与建议、模型和时间。未完成显示实际等待/执行状态，失败显示失败原因，过期记录不能作为当前镜头结果。返回后恢复原列表和滚动位置。详情按任务编号独立读取和更新，新增任务把该记录推到其他页时仍可查看；重新评测保留原筛选、搜索、页码和选择。只有当前仍存在、两侧有图、没有排队或执行中的边界可以明确重新评测。详情为类型专用内容，列表为通用展示组件，未来评测类型可以复用列表并注册专用详情；本次只接入真实存在的连续性评测，不展示未实现类型。

“发起评测”和“设置”为标题区域独立入口。发起评测显示当前相邻镜头列表与状态，选择具体边界并显式点击开始；先保存编辑再提交，明确模型与费用。缺图、未选模型、读取失败、执行中时说明原因并禁用提交。画面可用性独立于执行状态，旧任务显示完成或失败时仍检查当前两侧图片。默认没有新的批量付费操作。

设置使用独立表单页，自动评测默认关闭；关注阈值 0–100，明确为所有项目共享设置，保存结果清楚。进入面板、浏览任务、刷新与查询不触发付费模型。视频生成前原有风险确认不变，保持先保存后查询、等待明确继续、版本校验、卸载释放等待。

## 结构

- 通用列表组件只接收统一展示项与分页/指标/加载状态，发出选择、筛选和分页事件，不读取连续性时间线。
- 类型详情组件只渲染连续性记录，不负责请求。
- 原共享 ContinuityReviewPanel 负责查询、表单、显式请求和生成前确认，供视频制作与预演页复用。
- 服务端为现有历史任务 GET 添加可选状态和搜索过滤、全局计数；新增按版本与任务编号读取详情的 GET，不依赖列表页或最近 100 项。省略新字段保持旧响应契约兼容，不改评分算法或任务执行语义。

## 适配与验证

使用现有主题色、边框、柔和背景和规范按钮。抽屉与详情各自滚动，不横向溢出；手机宽度采用全屏面板。键盘可打开任务、返回、Esc 关闭，焦点恢复；屏幕阅读器可读任务状态、加载与错误。暗色主题使用变量，减少动画偏好得到尊重。

验证服务端跨页筛选与旧接口兼容，前端仅点击展示详情、返回恢复、查询竞态、分页、设置保存、缺图禁用、失败重试、重复提交防护与既有确认流程；两页实际浏览器宽窄屏、加载/空/离线/完成/失败/过期状态。浏览器使用模拟模型请求，不触发真实付费模型。
