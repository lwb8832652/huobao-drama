# 分镜画面与视频连续性设计

日期：2026-10-13。代码核对基线：dev@8b87cae；本地参考源码：/Users/liuwenbo/code/ArcReel，main@066e7a5。用户已授权按最佳方案优化分镜画面及视频连续性，本轮包含下述支持模型的首尾帧输入；实际视频抽帧串联留作后续能力。

## 口径

保留一个分镜段落规划 1～9 个静态关键画面、一次图片请求生成整张宫格并在本地切格的方式。沿用最新 dev 的整组生成自动采用、微调候选审核采用和历史版本切换。参考 ArcReel 的资产复用、联合生图和人工审核原则，增强分镜内部与相邻分镜之间的连续性。此次实现不恢复此前已撤回的“多个已有分镜联合成一张宫格”。

“一致性”需要分别处理人物身份与服装、场景空间与光色、动作状态与持物、视线与运动方向。剧情允许的转场、换装、机位变化必须保留。共享图片和提示词可以加强约束，不能保证模型输出完全一致；同一张图片作为两个视频的边界输入，也不保证边界附近的运动速度、镜头轨迹或实际输出像素完全一致。

## 已核对的现状

- previs-grid.ts 已读取绑定角色、场景、道具图片，并将 drama.style 与宫格提示词共同冻结。需要统一解析完整风格提示词，避免只使用风格名称。
- 宫格提示词已有整组约束和每格 continuity，但首次生成只读取当前分镜，未使用前一分镜结束画面及边界状态。
- frame-splitter-tools.ts 的规划上下文没有 imagePrompt、实际参考图片清单和前后分镜状态；模型请求依赖主动调用只读工具获取资料。
- continuity-review.ts 已比较相邻镜头的最后/第一张可用画面。这是生成后的审核，尚未反馈为生成前的输入约束。
- previs-batch.ts 的视频主流程当前使用 referenceImageUrls，firstFrameUrl 和 lastFrameUrl 均为空。部分适配器有首尾帧字段，不等于所有模型均支持，也不等于主流程已启用。
- 候选宫格已有版本历史。新方案必须保持旧记录可查看、回退，不能因扩大输入指纹校验而让全部历史候选不可用。
- 隔离分支 codex/frame-planning-references 中已有完整规划上下文及共享参考清单的后台实现，尚未合入以上 dev 基线。后续复用时需适配最新候选版本逻辑，不直接覆盖新 dev 文件。

## 三种方案与取舍

| 方案 | 做法 | 取舍 |
| --- | --- | --- |
| 仅强化文字 | 补充前后分镜状态与静态关键帧规划 | 改动少，但缺乏上一分镜实际画面的视觉依据 |
| 共享资产 + 边界参考（推荐） | 当前分镜一次出宫格，同场景时额外输入上一分镜已采用的结束格 | 保持当前成本结构，同时补充跨分镜视觉与动作约束 |
| 视频边界强绑定（本轮包含） | 关键连续镜头共用边界图，并按模型能力使用首尾帧视频生成 | 增强输入边界约束；实际输出仍需审核，实际视频抽帧串联留作后续 |

## 推荐一期设计

### 1. 共同参考素材

每次生成明确区分当前分镜的场景、出现的角色及服装版本、道具、用户上传参考与连续性参考。项目共享的是同一套资产及风格规则，每个分镜只发送本镜头相关资产，不发送全项目全部图片。

在服务端统一解析实际资产与完整项目风格。共同参考不被空的单格参考列表覆盖；合并 static 与 /static 的本地别名，保持参考图顺序和提示词编号一致。绑定资产缺失时先给出可修复原因，提交前拒绝调用模型。预览清单与候选冻结清单可分别展示“当前素材”和“本次实际使用素材”。

### 2. AI 规划

服务端直接传入分镜描述、视频动作、imagePrompt、时长、完整风格、资产身份、按时间排序的已有画格，以及相邻分镜的文字边界状态。模型不依赖工具调用才获得主要上下文。

每组生成开始状态、关键变化、结束状态；每格只描述当前可见的姿态、位置、持物、视线和光线。continuity 说明前一状态如何到达当前状态，不将一整段动作复制到每格。第一格还应说明它如何承接前一分镜结束状态；下一分镜尚未生图时，仅参考其剧本文字，不凭空生成额外图片。

保留 ID 与已有合理时间点；采用规划不自动生图。数量选择只修改本地选项，用户明确点击重新规划才调用文本模型；应用按钮使用当前实际草稿数量。

### 3. 相邻分镜的边界参考

沿当前时间线顺序寻找直接前一分镜，不能按数据库 ID 排序。连续性依据复用现有 transition.continuity、type、allowedChanges，不另造一套相互冲突的转场字段。

默认规则：

- 首个分镜：仅使用共享资产。
- 同场景、时间与剧情连续：引用前一分镜按时间排序的最后一格；必须是用户已采用的完整结束格，不使用未审核候选，也不以倒数第二格冒充缺失的结束格。
- 明确场景/时间切换或允许的变化：解除不适用的姿态、布局和光线约束。角色身份与当前服装、当前场景资产仍按当前分镜选择。
- 前一分镜尚无结束画面或其动作阶段不适合作为边界：显示“尚无可用上一分镜结束画面”，允许用户明确按共享资产独立生成，不额外生成一张桥接图。

提示词将边界图标为“上一分镜结束状态，仅用于当前第一格的动作衔接”，与人物/场景身份资产分开编号。人物身份和服装以当前明确绑定的资产为准，不能让上镜已有漂移覆盖权威资产。相同机位时可延续构图；反打、近景等切镜保留动作与空间逻辑，不能强制复制上一构图。

参考图上限必须包含编辑原图、共享资产和边界图。超限在提交前展示数量并调整，不能静默丢掉身份资产或已承诺使用的边界图。冻结边界来源版本、分镜 ID、画格 ID、图片摘要和适用连续性规则，实际上传字节与清单一一对应。

### 4. 生成、微调与失效

仍是一分镜一次联合宫格请求。整组生成沿用自动采用；微调候选审核后采用。切格和重新合成在本地完成，不产生额外模型调用。整图选格微调和切格后单格精修继续保留；未选格由程序保留原内容。

上一分镜结束格被修改或顺序变化时，依赖它的下游画面显示“衔接参考已变化”。已有图和历史候选保留；不自动连锁重生成，不自动覆盖下游画面。新请求读取最新已采用边界图。候选历史按其冻结依据展示，旧依据与现状不一致时明确提示，避免破坏现有版本回退功能。

当前页面按单个分镜显式生成，每次使用提交时已采用的前镜末格。连续制作时，先采用前镜，再提交后镜，后者便会取得最新边界。批量接口使用提交时已有的边界快照，不宣称使用同批刚生成的前镜结果。若后续加入自动顺序生成，依赖前镜的下一项必须等前镜被采用后再冻结输入；本轮不增加自动付费连锁任务。

### 5. 简化交互

宫格上方展示“参考素材 N 张”和“衔接上一分镜：第 X 镜·结束格”的紧凑缩略图。转场时显示“场景切换，动作衔接已解除”；无法确定时允许用户在高级设置调整连续性依据。

保持规划 → 生成宫格 → 审核采用 → 微调 → 生成视频的现有步骤，不增加强制审核页面。连续性审核复用现有能力，按用户操作运行，不在每次刷新或每次生图后自动增加付费评分。

## 本轮视频连续性增强

新增视频连续性选择 auto / reference / first_last。页面默认明确提交 auto：支持且画面齐全时采用首尾帧，单张或当前模型不支持时展示回退原因、继续现有参考图模式。旧请求未带该字段时保留参考图行为，已有视频仍可读取和回退。显式 first_last 对不支持的具体模型、组合视频或不足两张画面的请求，在创建任务之前拒绝。

首尾帧取当前分镜已采用的开始格、结束格并冻结实际文件；同场景、同时间且强连续、没有与共享边界冲突的允许变化时，下镜首帧取上镜同一结束格。正常切镜、反打或场景变化使用当前自己的首帧。图片角色、来源、摘要和实际采用模式存为独立快照，不能把有角标的宫格当作首尾帧。视频提示词仍包含中间关键状态与相应时点，模型首尾帧模式可能不能硬约束每个中间状态。

依据当前实现过的适配器：Wan 3.0 的两个已知模型和 MiniMax H3 支持首尾帧；Seedance 当前适配器及 Nuwax 未实现可靠尾帧传输，继续参考图模式。能力接口按配置与模型返回，不仅依据供应商名称推断。

界面将既有 transition 的 normal / strong / scene_change 表达为自动衔接 / 连续动作 / 场景切换，使用原时间线字段而非新造竞争配置。所有模式保留当前宫格版本和自动采用行为；用户可在画面区审核与通过历史切换。

区分“规划结束画面”和“实际视频最后一帧”。A 的规划尾格等于 B 的规划首格，只能保证输入层共用边界，无法证明 A 的实际视频恰好停在该图。

支持首尾帧的具体模型可让 A 的指定尾帧与 B 的指定首帧共用同一张审核后的边界图。连续同机位动作可启用，反打或正常切镜不默认共用同一像素画面。不支持首尾帧时明确保留参考图模式，不宣称强绑定。

首尾帧约束与多参考图/宫格输入是否可混用，必须由具体模型能力及适配器验证。例如当前 Wan 适配器对某些首尾帧与 reference 输入组合明确拒绝，不应简单把所有字段一起提交。

若使用 A 实际视频抽出的末帧作为 B 首帧，视频任务也需要顺序依赖；先审核 A 的实际末帧是否仍符合人物与场景资产，避免把已漂移的结果继续传给 B。此方式增加编排与审核要求，默认不启用。

## 验收依据

自动检查真实模型请求的资产/边界图字节、顺序、数量及提示词编号；检查数量选择零请求、一次显式生图一次请求、采用与切格零请求、上游修改不触发下游付费任务。覆盖结束格缺失、转场、时间线重排、资产缺失、参考上限、过时响应与历史回退兼容。

浏览器检查两个页面使用同一参考和规划交互。模拟提供商可以验证链路和调用次数；人物、动作、光色的一致性需用真实模型的少量同场景样例，经用户授权真实调用后逐格与跨镜审核，不能用模拟图片作为画面质量通过证据。
