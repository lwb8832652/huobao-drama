## 1. 原方案现状基线（历史代码记录）

本节保留原设计的代码定位，**不代表本次重新核验后的当前交付状态**；具体改造完成度另按 §16 验收。

### 1.1 后端
- 框架：Hono + `@hono/node-server`，端口 `PORT || 5679`（`backend/src/index.ts:103,116`）。
- API 挂载点：`app.route('/api/v1', api)`（`backend/src/index.ts:87`），共 20 个子路由：
  `dramas / episodes / storyboards / scenes / characters / tasks / task-queue / upload / ai-configs / ai-providers / style-presets / prompts / agent / merge / skills / props / storage / settings / server-update / previs`
- 健康检查：`GET /api/v1/health`（`backend/src/index.ts:58`），返回 `{status, version, timestamp}`。
- 静态资源：`/static/*` 走 `serveStaticRanges` + `serveStatic`，带 `Cache-Control: immutable`；支持 **Range/206**（`backend/src/middleware/static-range.ts`，`backend/src/index.ts:91-96`）。
- 前端产物：`app.use('*', serveStatic({root: FRONTEND_DIST}))`，**后端同时托管前端页面**（`backend/src/index.ts:98-101`）。
- 鉴权：原基线**无 JWT/无鉴权中间件**，仅 CORS 内网白名单正则（`backend/src/index.ts:49-55`）。
- Worker：6 个 `setInterval` 轮询，与主进程同进程（`backend/src/index.ts:108-122`）。
- MCP 代码：原基线不存在（`backend/src` 零匹配）；本轮不新增工具。

### 1.2 前端
- `frontend/app/composables/useApi.ts:1` → `const BASE = '/api/v1'`。
- `frontend/nuxt.config.ts:53-68`：dev 用 vite proxy `/api`、`/static` → `http://localhost:5679`；生产用 nitro `routeRules` 转发。
- 素材 URL：相对路径包含 `/static/`（`frontend/app/composables/useMedia.ts:12,27`）。

### 1.3 部署形态
- 原部署基线有 mysql/redis/milvus/es/nginx/frpc；P0–P1 不要求新增 Higress 或 Nacos 部署。现有网关的可选 Nacos 服务发现不因此被排除。

### 1.4 桌面端（关键约束）
- Electron 主进程 `utilityProcess.fork` 拉起后端，取随机空闲端口，窗口 `loadURL('http://127.0.0.1:<port>')`，**后端与窗口同源，前端全部相对路径，无 CORS**（`desktop/src/main.ts:6,233,243`）。
- 健康检查：`fetch('http://127.0.0.1:${port}/api/v1/health')`（`desktop/src/main.ts:81`）。
- 结论：桌面端接入入口会破坏“单进程同源”模型，需同时拉起两个进程并改健康检查与窗口地址，单机单用户场景暂不接入。

## 2. 目标与非目标

**P0 目标**：入口进程可启动、既有路由前缀可达、统一响应与错误码、日志与 Trace、健康检查、Huobao 反向代理可用（含 `/static` 与上传）。

**P1 目标**：纯 yudao-cloud 身份解析与透传、伪造身份头清理、租户提示兼容、两种长任务响应（等待模式透传 / 句柄模式返回 `task_id`）、健康探测与代理兼容性验证。真实 yudao 联调仍需单独验收。

**非目标**：数据库连接、领域逻辑、剧本/分镜/Agent 业务、MySQL 迁移（P2/P3）、nest-admin 本体、BullMQ、gRPC、Higress；不自建 JWT/Scope 授权体系，不扩展 MCP 工具或 OpenAPI。限流与生成并发控制暂缓。Nacos 属于现有网关可选服务发现，不要求本期新增部署。

## 3. 调用链

```text
Web ──▶ Hertz 入口 ──▶ Huobao(Hono)
  /web/huobao/v1/*  剥前缀 ──▶  /api/v1/*
  /static/*         直透   ──▶  /static/*
  /                 回源   ──▶  前端 dist（见 §8.3）
携带 Token 的请求 ──▶ yudao-cloud check-token ──▶ 解析身份后注入 login-user
登录/刷新/登出等请求 ──▶ 按现有路由转发下游；入口不签发 Token
MCP / OpenAPI ──▶ 保留既有边界，本轮不扩展
Electron ──▶ Huobao(Hono)（不接入口）
```

入口负责路由、远程身份解析、身份头清理与透传、协议适配、超时、日志与 Trace。是否需要登录、角色/权限及资源归属均由下游判断；入口不启用 `ScopeGuard`。Huobao 用户/租户维度仍需另行评估，不因入口透传身份而自动完成。

## 4. 路由规范与前缀剥除

| 入口路由 | 下游 | 下游路径 | 身份与授权边界 | 备注 |
|---|---|---|---|---|
| `/web/{app_code}/v1/*` | Huobao | `/api/v1/*` | yudao 身份透传；登录及业务授权由下游判断 | 剥 `/web/{app}/v1` |
| `/static/{app_code}/*` 或 `/static/*` | Huobao | `/static/*` | 本期默认放行，签名 URL 后续评估 | 必须保留 Range/206 |
| `/admin/{app_code}/v1/*` | 已配置管理下游 | 依路由配置 | yudao 身份透传；RBAC 及审计由下游负责 | 不引入入口侧授权体系 |
| `/mcp/{app_code}/*` | 既有配置 | 既有配置 | 保留既有行为 | 本轮不新增工具或凭证能力 |
| `/open-api/{app_code}/v1/*` | 既有配置 | 既有配置 | 保留既有行为 | 本轮不扩展 |
| `/healthz` `/readyz` | — | — | 无 | 入口自身 |
| `/` 及未匹配 | Huobao 前端 dist | 原样 | 无 | 见 §8.3 |

限流桶与生成并发控制暂缓，不是上述路由的本轮验收条件。

**剥前缀规则**：只剥一次、按字面量匹配，`app_code` 必须命中注册表，否则 `40402 APP_NOT_FOUND`。禁止正则回溯改写路径；路径其余部分与 Query 原样透传。URL Fragment 不会随 HTTP 请求发往入口。

**安全目标**：下游返回 3xx 时，内网绝对 `Location` 按注册表的 `public_base` 重写，避免内网地址泄漏；完成度须验证，不由本稿推定。

## 5. 接口契约

### 5.1 统一响应体

成功：原样透传下游 body（入口不包裹，避免破坏现有前端解析）。入口自身产生的代理错误沿用统一格式：

```json
{
  "code": 50201,
  "message": "downstream unavailable",
  "request_id": "01J9...",
  "data": null
}
```

前端错误解析应区分入口代理错误与 yudao/业务下游响应；不能仅凭 HTTP 2xx 推断 yudao 业务码成功，也不将下游登录/授权错误改写为入口 Scope 错误。

### 5.2 错误码边界

| code | HTTP | 含义 | 范围 |
|---|---|---|---|
| 40001 | 400 | 参数错误 | 路径/Query/body 非法 |
| 40002 | 400 | 请求体过大 | 超过配置上限 |
| 40401 | 404 | 路由不存在 | 未匹配注册路由 |
| 40402 | 404 | 应用未注册 | `app_code` 不在注册表 |
| 50201 | 503 | 下游不可用 | 拨号失败/连接被拒 |
| 50202 | 502 | 下游响应异常 | 非法响应或代理错误映射 |
| 50401 | 504 | 下游超时 | 路由预算耗尽且尚可返回错误体 |
| 50001 | 500 | 入口内部错误 | 未捕获异常 |

旧表中的入口 `40101/40102` 本地 Token 校验、`40103` Scope 拒绝、`40301` RBAC 拒绝不再是本轮入口契约；登录与授权失败按 yudao/业务下游处理。`42901` 限流暂缓。普通代理错误不得泄露下游堆栈、Token 或内部消息。**响应已开始写出后不能再改 HTTP 状态或追加统一 JSON 错误体**，应终止流并记录原因。

### 5.3 内部请求头契约

- 身份唯一来源是远程 `check-token` 结果；只沿用 yudao 的 `login-user`，不双写 `X-User-Id`、`X-User-Scope` 等自定义身份头。
- 客户端伪造的 `login-user` 及旧自定义身份头必须清理；解析成功后才构造可信 `login-user`。匿名请求不得保留客户端伪造身份。
- `Authorization` 沿用 yudao 转发契约，不替换为入口重签的内部 JWT。
- `tenant-id` 是不可信租户选择提示：只接受非负 int64 并规范化，非法、负数或溢出值删除。无 Token、无效/过期 Token 或鉴权网络失败均保留合法提示、不带身份放行，不返回入口认证错误；有效 Token 的 `check-token` 结果覆盖 `tenant-id`。租户提示会转发给 `check-token`，并与 Token 一起区分缓存，不能冒充已认证身份。
- `X-Request-Id`、`traceparent` 等只承担请求关联与 Trace，不构成用户或授权凭证；路由元数据同样不能作为业务鉴权依据。

### 5.4 健康检查契约

| 端点 | 依赖下游 | 语义 |
|---|---|---|
| `GET /healthz` | **否** | 进程级存活；下游抖动不得摘入口实例 |
| `GET /readyz` | 按 readiness 配置 | 启用下游探测时必须进行真实探测，不能只检查发现列表非空 |
| `GET /web/huobao/v1/health` | 是 | 透传 Huobao `/api/v1/health`，用于 Web 巡检；桌面端仍直连 |

`READYZ_PROBE_DOWNSTREAM=false` 默认仅反映自身状态；开启后与代理共享 resolver，执行真实 `Probe`：**每应用 2s 预算，并行探测可用实例，任一完成有限 HTTP 读取即可达**。Probe 不得吞掉截断或超时读取错误，也不能让顺序探测的慢首节点耗尽预算而漏掉健康备用实例。无实例或预算内所有实例均不可达返回 HTTP 503，全部应用可达才返回 200。验证记录：静态 HTTP/HTTPS、默认端口、应用编码到 Nacos 服务名 alias、readiness 无实例/不可达/健康备用实例，以及 Probe 读取异常相关 Go 回归随全量测试和 race 测试通过；真实 Nacos 下注册/注销与 readiness 联动结果见 §16.4。这些结果均不等同于真实 yudao 业务全链路通过。

### 5.5 登录与 Token 契约（纯 yudao-cloud）

- 登录、刷新、登出由现有下游负责，入口按已配置路由转发；废弃 V1.1 自建 `/auth/login`、`/auth/token`、JWKS 和签发桩承诺，不保证“未来只换两个变量即可零改动”。
- 入口通过 yudao-cloud 远程 `check-token` 解析 Token，不做本地 RSA/JWT/JWKS 验签，不维护自有账号、Refresh Token 或签名密钥。
- 缺 Token、无效/过期 Token 与远程校验网络失败均不返回入口认证错误，而是清理身份后匿名放行，并保留合法租户提示；下游必须保护需要登录的接口。已有有效缓存的命中与截止规则按认证实现处理，不提供本地验签兜底。
- 真实 Java 源码核实结果：`GatewayJacksonAutoConfiguration` 与 Web starter 均注册 `TimestampLocalDateTimeSerializer/Deserializer`，`expiresTime` 为 **JSON 数字 epoch-millis**，不是 ISO 无时区字符串。Go `login-user` 输出数字毫秒，`check-token` 响应解析接受数字并兼容字符串；兼容无时区字符串按 Go 进程本地时区解释。该结论为源码核实与 Go 测试，**尚非真实 yudao 服务全链路验证**。
- `ScopeGuard` 不启用，不配置入口路由 Scope，也不将其列为待补能力。是否需要登录、角色/菜单/权限和资源归属均由下游判断。

## 6. 超时分级表

以下保留原设计预算作为**目标值**，不是当前配置默认值或已验证结论；实际配置项、首字节和整体超时的支持范围以网关为准。

| 路由类别 | 拨号 | 首字节(TTFB) | 整体 | 说明 |
|---|---|---|---|---|
| 读 `GET` 列表/详情 | 2s | 5s | 15s | 幂等，可按策略重试 |
| 写 `POST/PUT/DELETE`（非生成） | 2s | 10s | 60s | 不自动重试 |
| 生成类 `agent/*`、`tasks/*`、`merge/*`、`previs*`、`task-queue/*` | 2s | 30s | **900s(15min)** | 等待模式；句柄模式立即返回 |
| 上传 `upload` | 2s | 60s | **1800s(30min)** | 流式转发，独立 body 上限 |
| 静态 `/static/*` | 2s | 10s | 300s | Range 分段各自计时 |
| 管理 `/admin/*` | 2s | 5s | 30s | 独立预算 |
| MCP / OpenAPI | 沿用现有配置 | 沿用现有配置 | 沿用现有配置 | 本轮不扩展 |

拨号失败应及时返回 `50201`。长流预算必须覆盖读取响应体全过程，不能在拿到响应头时提前释放上下文、取消计时或释放下游资源。**504 仅在响应尚未开始时可返回**；流式响应已提交 200 后发生预算超时，仅取消上游并终止传输，不修改状态、不追加错误 JSON。

真实 Hertz TCP 验证记录： `TestProxyStreamsEventsOverTCP`、`TestProxyStreamBudgetOverTCP` 重复 5 次通过：首个 SSE 事件在上游结束前送达、后续分块完整；流中预算超时取消上游且保留 200。已知 Hertz v0.10.6 对未知长度 chunked 响应会吞掉 reader 非 EOF 错误并发送正常结束块，客户端可能收到部分内容加正常 EOF，**不能只用 HTTP 200 或 EOF 判断业务完成，应检查业务完成事件**。这不是新增下游事件协议的实现承诺。`app.New` 已启用 Hertz `server.WithSenseClientDisconnection(true)`，在当前默认 **netpoll transport** 下客户端断开会主动取消上游、回收在途资源：真实 TCP 测试中首事件后客户端 `body.Close`，上游 context 在 1s 内取消，不等待 5s 预算；该用例及 SSE 两块/流中预算用例均经 race 模式重复 5 次通过。此开关仅支持 netpoll，切换其他 transport 必须重新验证；这些定向测试仍不证明 15 分钟长流或压测通过。

本轮不要求新增限流桶、并发信号量、超限错误或跨实例计数。未来是否恢复及具体阈值需另行确认，不作自动补齐承诺。

## 8. 特殊通道

### 8.1 `/static` Range 与缓存
- 必须透传 `Range`、`If-Range`、`If-None-Match`、`If-Modified-Since`；下游 206/304 原样返回。
- 保留 `Cache-Control: public, max-age=31536000, immutable`。
- 禁止在入口做完整响应体缓冲（会破坏大视频分段）；使用流式拷贝。
- 本期静态资源默认放行；不可猜 UUID 不等于访问控制，P2 再评估签名 URL。

### 8.2 上传 `upload`
- 原设计 body 上限为普通请求 1MB / 上传 2GB；本稿保留目标，不将其宣称为已生效默认值。
- 流式转发，避免完整请求体缓冲，保留 `Content-Type: multipart/form-data` 边界。
- 上传限流暂缓，不以 `web.upload` 桶作为验收条件。

### 8.3 前端 dist 回源
现状由 Hono 托管（`backend/src/index.ts:98-101`）。P0 提供 `/` → Huobao 回源（透传静态与 SPA fallback）。
**建议**：生产环境前端独立部署（对象存储/部署平台），Hertz 只承担 API 入口；回源仅作为过渡，需在评审确认。

### 8.4 长任务两种响应
- **等待模式**（现有行为）：透传下游流式/长连接，禁用完整响应缓冲，按 §6 管理响应体全生命周期。
- **句柄模式**：下游返回 `task_id`，入口原样返回；客户端凭已有 `task_id` 轮询 `tasks`/`task-queue`。
- 本期**不改** Huobao 任务语义。仅在已取得可查询 `task_id` 且下游支持查询时才能恢复；不能承诺所有等待模式断线均可恢复。

| 场景 | 原设计策略 / 当前边界 |

实际字段与 Trace 支持程度须按当前日志核验，不能仅凭此列表宣称完成。

**禁止记录**：Token、Authorization、`login-user` 内容、请求/响应正文、Cookie、上传文件内容。必要身份关联只记录受控字段，不记录完整认证响应。

Trace 目标：`traceparent` W3C 透传，缺失时补齐请求关联。业务动作审计由下游负责；入口不新增 Admin RBAC 与业务审计能力承诺。

## 12. 降级矩阵

| 故障 | 行为与验证边界 |
|---|---|
| yudao 登录/刷新下游不可用 | 按实际代理错误处理；入口无签发桩或本地续签兜底 |
| `check-token` 不可用 | 有效缓存按既有缓存策略命中；需要远程校验但网络失败时，保留合法租户提示、不带身份放行，不返回入口认证错误。不存在 JWT 本地验签兜底，也不凭客户端 Token 内容生成身份；下游必须保护受限接口 |
| 无 Token / 无效或过期 Token | 始终移除伪造身份，保留合法租户提示、不带身份放行；不返回入口认证或 Scope 错误，登录与业务授权由下游判断 |
| Huobao 不可用 | 拨号失败 → `50201`；不自动重试写入 |
| Huobao 超时 | 未提交响应时按预算返回 `50401`；已开始响应则终止流并记录，不追加 JSON |
| 生成中长连接中断 | 只有已取得可查询 `task_id` 时才能按下游能力恢复；不承诺透明接管或自动重建任务 |
| Worker 停止 | 任务持久化及恢复属于 Huobao 职责；本期仍沿用现有 SQLite，不预设已迁移 MySQL |
| 入口实例宕机 | 新请求可由其他健康实例处理；已有连接会断开，下游已持久化任务不由入口托管 |

9. **既有重定向风险**：代理与 `check-token` HTTP 客户端沿用默认自动重定向，3xx 尚不保证原样透传；跨目标重定向可能外传自定义身份头或含 Token 查询参数的 Referer。本轮文档与兼容性提交未修复该原基线风险，生产部署前需限制重定向并补测试。
10. **既有重试与降级测试缺口**：当前重试仅判断 GET/HEAD/OPTIONS，尚未排除生成类路径，与 §9 的目标存在差距；原有旧缓存降级测试未保证 TTL 过期或断言失败拉取发生，真实 Nacos 故障降级仍需专项验证。本轮不将以上事项写成已修复。

## 18. 数据库结论（P0–P1）

**入口不需要新增数据库。**下游沿用现有存储，远程 yudao 认证不等于入口连接其数据库。

| 组件 | P0–P1 存储 | 说明 |
|---|---|---|
| 统一入口（Hertz） | 无新增数据库 | 注册/发现与身份缓存按当前实现管理；限流与生成并发暂缓 |
| yudao-cloud | 已有下游服务自身存储 | 入口仅调用认证接口，不维护账号与 Token 签发数据 |
| Huobao | 现有 SQLite（`data/huobao.sqlite3`） | 不改驱动、Schema、路径 |
| 任务状态 | 现有 SQLite `sys_task` | 已持久化任务不依赖入口存活，连接中断不等于任务自动可恢复 |

原 authstub 内存账号/Refresh Token 存储方案已废弃。后续平台数据库、Huobao MySQL 迁移、Redis/BullMQ 均需另行评估，不由本稿引入。
